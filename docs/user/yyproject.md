# yyproject

タスク・課題・進捗を管理します。Windows GUIは `yyprojectw`、AI向けMCPサーバーは `yyproject` です。MCPはWindowsとLinuxに対応します。SQLiteは同梱しており、外部DBサーバーは不要です。

## 起動

```powershell
yyprojectw C:\projects\team.sqlite3
yyproject --init-demo C:\projects\sample.sqlite3
yyprojectw C:\projects\sample.sqlite3
```

ファイル未指定の場合、GUIは `%LOCALAPPDATA%\YYProject\projects.sqlite3` を使用します。ファイル → プロジェクトを追加で名前・開始日・完了予定日を登録します。1つのDBに複数プロジェクトを保存し、画面上部で切り替えます。

## 同梱デモ

[デモDBと操作例](../../demo/README.md)を用意しています。`demo/yyproject-demo.sqlite3` をコピーしてGUIで開くと、YYシリーズを題材にした3案件・90項目、マスタ、依存関係、追加要求・差し戻しを含む進捗を確認できます。すべて架空のデータです。デモフォルダは配布アーカイブにも含まれます。

## 表示と編集

| 表示 | 用途 |
| --- | --- |
| カンバン | 未着手・進行中・保留・完了・中止の列へ項目を表示。カードのドラッグで状態を変更 |
| ガント | 開始日・期限・進捗を表示。土日と休日マスタの休日を区別 |
| タスク一覧／課題一覧 | 件名・状態・担当者・カテゴリ・日程・工数・進捗を表で確認 |
| 依存ネットワーク | 先行項目から後続項目への矢印を表示 |
| バーンダウン | 記録した残工数の推移 |
| バーンアップ | 完了工数と総工数の推移 |
| マスタ | カテゴリ・担当者・休日の登録内容 |

編集メニューで項目・マスタ・依存関係を追加します。項目を選んで編集、またはダブルクリックします。タスクの編集画面は基本情報・日程と進捗・説明を切り替えて入力します。担当者とカテゴリはマスタから選択します。期間は営業日（0は1営業日として計算）、工数は時間、進捗は0～100%です。完了状態では100%になります。中止した項目はチャートの集計から除外します。

依存関係には待機営業日を設定できます。「営業日で日程を再計算」は、各項目の開始指定と先行項目の期限を考慮し、土日・休日を除いて日程を更新します。循環した依存関係は登録できません。担当者のリソース平準化は行いません。

幅が狭い場合、表示タブは横にスクロールします。表示メニューからも画面を切り替えられます。ホイールは縦、Shift＋ホイールは横に移動します。スクロールバーも使用できます。

## 保存とAIの連携

変更は即座にSQLiteへ保存します。同じホスト上のMCPとGUIがローカルディスク上の同じDBを開く場合、プロジェクト版の競合を検出して上書きを拒否します。別プロセスでの変更はGUIへ再読み込みします。LinuxのMCPは独立して利用でき、Windows GUIとの遠隔DB共有サービスは提供しません。ネットワーク共有フォルダをDBの保存先にしないでください。進捗はローカル日付ごとに記録し、同日の最新状態を使います。過去の記録は後日の変更で置き換えません。

ファイル → プロジェクトをJSON出力で、項目・マスタ・依存関係・進捗記録を出力できます。これはDB全体と監査ログのバックアップではありません。WAL使用中のDBをバックアップするときはアプリとMCPサーバーを終了してからSQLiteファイルをコピーしてください。

[同梱ヘルプ・MCP設定と操作スキーマ](../../help/help.md)を参照してください。GUIのヘルプは既存YYシリーズと共通のMarkdownビューアーを使い、WebView2がない場合はテキスト表示へ切り替わります。

## 絞り込みと安全な状態変更

「絞り込み → 検索条件を設定」で、件名・説明の部分一致（英字は大小を区別しない）、担当者、カテゴリ、状態、未完了、期限超過、未割当を組み合わせます。対象はカンバン・タスク一覧・課題一覧です。期限超過はローカルの本日より前の期限を持つ未完了項目、未割当は担当者未指定の未完了項目です。「すべて解除」で解除し、案件を切り替えると条件を初期化します。フッターに一致件数を表示します。ガント・依存図・進捗チャートは案件全体を表示します。優先度・重大度・レビューも条件に指定できます。条件の保存と並べ替えは未対応です。

カンバンの見出しには条件に一致する件数を表示します。案件選択時やカンバンへ切り替えた時は、カードがある最初の状態の列へ移動します。「カンバンの列」メニューから各状態へ直接移動できます。完了案件も完了カードから確認できます。

完了済みの項目を再開する際は、残作業を反映するため0〜99%の進捗を入力します。状態メニュー・ドラッグでは専用入力が開き、項目編集では「日程・進捗」で変更します。100%のままの再開はGUI・MCPとも拒否します。先行項目に未完了・中止の項目がある後続項目は完了にできません。不要な依存は明示的に解除してください。既に完了している項目の説明などは編集できます。

## 日程の再計算と確認

「営業日で日程を再計算」は、保存前に開始日・期限の変更差分と案件終了日を超える項目を表示します。確認欄で適用を明示して保存します。納期超過がある場合は、その承認を選ぶ必要があります。キャンセルでは保存しません。開始日と期限が両方ある完了・中止項目の日付は保持し、日付が欠けている項目は計算します。承認時のプロジェクト版が古ければ競合として拒否します。

この承認は操作した本人による確認です。別の承認者を要求する仕組み、基準計画と実績日の分離、リソース平準化、取り消し操作は未対応です。

## 分類・レビュー・対応タスク

項目編集の「分類・確認」タブで優先度（低／通常／高／最優先）、重大度（未指定／軽微／重大／致命的）、レビュー（確認不要／確認待ち／承認済み／差し戻し）と確認者を設定します。確認者は担当者マスタから選びます。「確認メモ」タブに確認結果と理由を記入します。承認・差し戻しには理由が必要です。確認待ち・差し戻しの項目は、進捗が100%でも完了にできません。作業状態とレビュー状態は別々に扱います。

分類とレビューは一覧の列とカンバンに表示し、絞り込み条件にも使えます。レビューの記録は通常の更新監査へ残ります。確認者本人の認証や権限による承認制御は提供していないため、確認者を選ぶことを本人の操作の証明とは扱いません。

課題編集の「集計・関連」で、対応するタスクのIDをカンマ区切りで指定できます。課題からタスクへの関連付けであり、作業順序を制御する依存関係とは別です。存在しないID、課題のID、重複IDは拒否します。

同じタブで「工数に算入／集計から除外」を選びます。除外項目は総工数・完了工数・残工数に算入しませんが、入力した見積もりと進捗は保持します。新しく「課題を追加」で作る項目は除外が既定で、対応タスクへ作業工数を記録する運用を想定しています。既存項目とMCPで指定を省略した項目は従来どおり算入します。関連付けだけで自動的に工数を除外しないため、既存の課題は必要に応じて変更してください。過去の進捗履歴は通常の編集では再計算しません。

## 保管・復元

項目を選んで「編集 → 選択項目を保管」を開くと、無効になる依存関係と関連課題を確認できます。適用を明示して保管し、キャンセルでは保存しません。保管した項目は通常の一覧・カンバン・ガント・依存図・現在の工数集計から除きます。依存関係はデータとして保持し、保管項目につながる関係を日程計算・完了ゲート・依存図では無効にします。後続作業を阻止する関係も外れるため、保管前に影響を確認してください。

「絞り込み → 保管済みの項目を表示」で保管項目を確認し、「編集 → 保管した項目を復元」で選択して復元できます。同じID、全項目、依存関係を保持して戻します。関連課題からの参照も保持します。復元後は通常の絞り込みへ戻ります。

保管項目から参照される担当者・カテゴリ・確認者のマスタも削除できません。保管項目は20,000件の上限に含まれます。完全消去や保管世代の自動整理は未対応です。マスタの削除は保管ではなく削除です。形式2のDBは旧バージョンのアプリでは開けません。形式1は読み込め、最初の正常な書き込みと同時に形式2へ更新します。以前のアプリへ戻す必要がある場合は、更新前に終了済みDBのバックアップを残してください。
