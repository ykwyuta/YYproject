# 左メニューのちらつき・文字欠落修正（2026-10-27）

v0.4.0のWindows版で、左メニューが灰色の四角だけになりちらつく報告を受けた。レイアウト変更・フォーカス変更中にWindowsが同期的に送るWM_DRAWITEMを、APPのRefCell借用中という理由でスキップしていた。既存の画像試験はStateの描画関数を直接呼んでいたため、このメッセージ経路の欠落を検出できていなかった。

描画に必要なフォント・DPI・選択画面をコピー可能な情報として分離し、WM_DRAWITEMをAPPの借用前に処理してTRUEを返すよう修正した。起動時・レイアウト時・DPI変更時に情報を更新する。ボタンはバッファーで描いて一度に表示し、サブクラスで先行する背景消去を抑える。不要な表示切り替えと同一位置への移動も避ける。保存処理、依存ライブラリ、Git依存SHAは変更しない。

## 検証結果

- Windows: fmt、全workspace/all-targets Clippy（警告エラー）、Rust 36件成功。releaseビルド成功。
- 専用DB・所有ウィンドウによるWindows GUI smokeがdebugとreleaseで成功、所有プロセス終了コード0。実DPIは192。既存の編集・コピー・一括更新・ドラッグ・フィルター・寸法変更・各管理画面も通過した。
- 新規回帰試験はAPPを実際に可変借用したままWM_DRAWITEMを親ウィンドウへ送信し、TRUEが返ること、全15画面の選択／非選択ボタンで背景色と白い文字の画素を確認する。背景消去メッセージが既存画素を壊さないことも確認した。描画関数の直接呼び出しによる代用ではない。
- 画像取得も親ウィンドウのWM_DRAWITEMを通すよう変更した。[修正後の左メニュー](images/yyproject-sidebar-repaint.png)は専用ウィンドウのオフスクリーン描画で、デスクトップ全体の撮影や動画の性能計測ではない。
- Linux: Docker上でfmt／Clippy、Rust 35件、実stdio MCP成功。Windows GUIの成功とは区別する。

[Windows release実状態ログ](evidence/yyproject-sidebar-repaint.txt)。試験は期限付きの実状態で判定した。利用者のデモDB2個は変更・コミットせず、分離ソースのデモは両方ともGitの配布用データを使用する。ここでの成功はローカル検証を指す。
