# カンバン操作・文字表示の改善（2026-10-27）

## 原因と変更

元の実装は押下時にタスクIDだけを保持し、離した位置で状態を変更していた。移動中のマウス処理・追従表示・端の自動スクロールがなく、幅の狭い画面では離れた列へ移動しにくかった。

- DPI別の開始閾値、つかんだ位置を保つ追従カード、移動先の枠、端での自動スクロールを追加。
- Esc、右クリック、領域外へのドロップ、キャプチャ喪失、非アクティブ化、案件・表示変更でキャンセル。クリック・同じ状態への移動は保存しない。
- 通常の状態更新経路を使い、先行タスクの完了条件、再開時の残作業、競合検出、監査を維持。
- 件名を2行にして情報行と分離。余白もDPIに追従させ、再描画をメモリDC経由に変更。
- 一覧の期限列を日付に必要な幅へ拡大。内容幅を列幅の合計から求め、右端の関連タスク列までスクロール可能にした。
- 項目の右クリックメニューから編集・状態変更できるようにした。省略された件名の全文は編集画面で確認できる。
- 操作説明と埋め込みヘルプ、現行内部仕様を更新。依存関係・ライセンスに変更なし。

## 検証

Windowsで以下を確認した。

- `cargo fmt --all -- --check`: 成功。
- `cargo clippy --workspace --all-targets --locked -- -D warnings`: 成功。
- `cargo test --workspace --locked`: 16件成功、除外なし。
- `cargo build --workspace --release --locked --target-dir target/kanban-build`: 成功。
- `python tools/test_mcp.py target/kanban-build/release/yyproject.exe`: 実際のstdioによるUnicode保存、版競合、監査、読み取り専用、保管・復元など成功。
- `python tools/validate_operations.py target/kanban-build/release/yyproject.exe`: 3案件・90項目の運用シナリオを実行。既存の対応10項目・未対応2項目を記録。
- 新規専用ディレクトリでリリース版の `yyprojectw --ui-smoke-test NEW_DIRECTORY`: 終了コード0。所有プロセスの終了を期限60秒で確認・回収した。
- GUIの実DPIは192。外形1100×700と640×480で8画面を検証。クライアント領域・現在のスクロール・実ヒット領域を使い、ドラッグの追従、端のタイマーによるスクロール、保存後のDBの完了状態と版増分、キャンセル、同じ列への移動による無更新を確認。右端へスクロールした一覧の最終列でも行選択できることを確認した。
- 右クリックのネイティブメニューを開き、編集と5状態の選択肢、キャンセル後の無更新を確認した。
- 件名の折り返しと日付・右端列の描画を画像で確認。画像は本番キャンバスの描画であり、ネイティブ子コントロールは含まない。
- 更新文書の相対リンク、CLIの埋め込みヘルプ、NOTICE・COPYING・COPYING.EXCEPTION・licensesの存在を確認。依存更新はない。

既存の `target/release/yyprojectw.exe` はアクセス拒否で置き換えられなかったため、既存ファイルを終了・削除せず別の出力先へビルドした。一時領域のアクセス拒否はTEMP/TMPを作業領域内の `target/task-temp` に設定して回避した。Clippy実行時の増分キャッシュのハードリンク警告は `CARGO_INCREMENTAL=0` でキャッシュを使わず再実行した。ソースの警告抑制は追加していない。

最終GUI記録は `target/ui-kanban-verified-0b79f0018c114aabad487041d30dcf94/ui-smoke.txt`。画像・DPI・描画範囲のJSONも同じディレクトリに出力した。利用者のDBや設定は操作せず、既存のデモDBの作業差分も保持した。

Linuxは未検証（この環境のWSLは起動時にアクセス拒否）。CIは実行・結果確認していない。別DPIでの実機操作は未検証。
