# yyproject

タスク・課題・進捗をSQLiteまたはPostgreSQLに保存するプロジェクト管理アプリです。

Windows GUI: `yyprojectw [DATABASE]`

Windows / Linux MCP: `yyproject --mcp DATABASE [--read-only]`

同梱デモ: 配布フォルダの `demo/yyproject-demo.sqlite3` をコピーしてGUIで開けます。YYシリーズの架空の3案件・90項目と、マスタ・依存・進捗履歴を収録しています。詳しくは配布物の `demo/README.md` を参照してください。

サンプル作成: `yyproject --init-demo NEW_DATABASE`

バージョン: `yyproject --version`

SQLiteは同梱しています。MCPの標準出力はJSON-RPCメッセージ専用です。

## データの扱い

同じホスト上のGUIとMCPは、ローカルディスク上の同じデータベースを開けます。ネットワーク共有上のDBは使用しないでください。複数PCで共有する場合はPostgreSQLモードを利用します。更新時はプロジェクトの版番号を確認し、競合時には上書きせず再読み込みを求めます。変更は即座にトランザクションで保存します。WALモードを使用するため、起動中にSQLite本体ファイルだけをコピーせず、終了後にバックアップしてください。

工数は時間、進捗は0～100%です。完了時は100%になり、中止した項目は集計対象外です。バーンダウンは残工数、バーンアップは完了工数と総工数を表示します。同日の記録は最新状態に更新し、通常の編集では過去の日付の記録を変更しません。MCPのcaptureで日付を明示すると、その日の記録を現在の集計値に置き換えます。過去データがない期間の実績は生成しません。

依存関係は先行項目の完了後に後続項目を開始する関係です。循環・不明な項目への参照を拒否します。期間は営業日単位で、0は1営業日として計算します。日程再計算は土日・休日マスタを除き、期間と先行項目の終了・待機営業日から開始日と期限を計算します。担当者のリソース平準化は行いません。

## MCP設定

MCPクライアントの設定例（パスは実環境に置き換えてください）:

```json
{"mcpServers":{"yyproject":{"command":"yyproject","args":["--mcp","/path/to/projects.sqlite3"]}}}
```

`project_list` / `project_get` でプロジェクトと版を読み、`project_create` で新規作成します。`project_change` には `project_id`、`expected_revision`、`actor`、`change` を指定します。

```json
{"project_id":1,"expected_revision":1,"actor":"AI","change":{"operation":"save_task","task":{"title":"要件を整理する","estimate":8,"duration_days":1,"status":"todo"}}}
```

変更操作は `rename`、`save_task`、`remove_task`（保管）、`restore_task`、`save_master`、`remove_master`、`add_dependency`、`remove_dependency`、`schedule`、`capture`。新規タスク・マスタのIDは0です。既存タスクは全項目置換なので、まず現在のタスクを取得してください。日付はYYYY-MM-DD。マスタの種類はcategory・assignee・holidayで、休日にはdateが必要です。使用中のカテゴリ・担当者を削除すると失敗します。

`task_list` はstatus・kind・query・assignee・category・unassigned・incomplete・overdue_beforeによるAND絞り込みとoffset・limitのページング、`audit_list` は変更履歴のページングに対応します。スキーマの詳細は `tools/list` を参照してください。

プロジェクトは最大20,000項目・100,000依存関係、日程は最長10年です。MCPの1メッセージ上限は2MiBです。任意SQLの実行や、クライアントからのDBパス切り替えは提供しません。

## 絞り込みと安全な状態変更

「絞り込み → 検索条件を設定」で、件名・説明の部分一致（英字は大小を区別しない）、担当者、カテゴリ、状態、未完了、期限超過、未割当を組み合わせます。対象はカンバン・ガント・タスク一覧・課題一覧です。期限超過はローカルの本日より前の期限を持つ未完了項目、未割当は担当者未指定の未完了項目です。「すべて解除」で解除し、案件を切り替えると条件を初期化します。フッターに一致件数を表示します。依存図・進捗チャートは案件全体を表示します。優先度・重大度・レビューも条件に指定できます。条件の保存は未対応です。行の順序はID欄のドラッグで変更できます。

カンバンはカードを押したまま動かすと、カードがマウスに追従し、移動先の列を枠で強調します。表示領域の左右・上下の端に近づけると自動スクロールします。移動先の列で離すと状態を保存します。Esc・右クリック・表示領域の外で離す操作でキャンセルできます。クリックだけでは状態を変更しません。カードの件名は2行まで表示し、長い件名は末尾を省略します。全文はダブルクリック、Enter、または右クリックの「項目を編集」で確認できます。右クリックメニューから状態を直接変更することもできます。

カンバンの見出しには条件に一致する件数を表示します。案件選択時やカンバンへ切り替えた時は、カードがある最初の状態の列へ移動します。「カンバンの列」メニューから各状態へ直接移動できます。完了案件も完了カードから確認できます。

完了済みの項目を再開する際は、残作業を反映するため0〜99%の進捗を入力します。状態メニュー・ドラッグでは専用入力が開き、項目編集では「日程・進捗」で変更します。100%のままの再開はGUI・MCPとも拒否します。先行項目に未完了・中止の項目がある後続項目は完了にできません。不要な依存は明示的に解除してください。既に完了している項目の説明などは編集できます。

## 日程の再計算と確認

「営業日で日程を再計算」は、保存前に開始日・期限の変更差分と案件終了日を超える項目を表示します。確認欄で適用を明示して保存します。納期超過がある場合は、その承認を選ぶ必要があります。キャンセルでは保存しません。開始日と期限が両方ある完了・中止項目の日付は保持し、日付が欠けている項目は計算します。承認時のプロジェクト版が古ければ競合として拒否します。

この承認は操作した本人による確認です。別の承認者を要求する仕組み、基準計画と実績日の分離、リソース平準化、取り消し操作は未対応です。

## MCPの再計画プレビュー

`schedule_preview` に `project_id` を指定すると、`revision`、変更差分 `changes`、終了日超過の項目ID `overdue_ids` が返ります。読み取り専用でも利用でき、DB・進捗・監査を更新しません。確認後に以下の操作を行います。

```json
{"project_id":1,"expected_revision":42,"actor":"planner","change":{"operation":"schedule","allow_overrun":false}}
```

`allow_overrun` の省略はfalseで、納期超過なら保存全体を拒否します。超過を承認する場合だけtrueを指定します。この指定は監査ログへ残ります。プレビューの版番号をexpected_revisionに使い、競合したらプレビューからやり直してください。

`task_list` の `overdue_before` はYYYY-MM-DDの基準日で、その日より前の期限を持つ未完了項目を抽出します。`unassigned` と `incomplete` は真偽値、担当者・カテゴリは正のマスタIDです。例: `{"project_id":1,"unassigned":true,"incomplete":true}`。

## 分類・レビュー・対応タスク

項目編集の「分類・確認」タブで優先度（低／通常／高／最優先）、重大度（未指定／軽微／重大／致命的）、レビュー（確認不要／確認待ち／承認済み／差し戻し）と確認者を設定します。確認者は担当者マスタから選びます。「確認メモ」タブに確認結果と理由を記入します。承認・差し戻しには理由が必要です。確認待ち・差し戻しの項目は、進捗が100%でも完了にできません。作業状態とレビュー状態は別々に扱います。

分類とレビューは一覧の列とカンバンに表示し、絞り込み条件にも使えます。レビューの記録は通常の更新監査へ残ります。確認者本人の認証や権限による承認制御は提供していないため、確認者を選ぶことを本人の操作の証明とは扱いません。

課題編集の「集計・関連」で、対応するタスクのIDをカンマ区切りで指定できます。課題からタスクへの関連付けであり、作業順序を制御する依存関係とは別です。存在しないID、課題のID、重複IDは拒否します。

同じタブで「工数に算入／集計から除外」を選びます。除外項目は総工数・完了工数・残工数に算入しませんが、入力した見積もりと進捗は保持します。新しく「課題を追加」で作る項目は除外が既定で、対応タスクへ作業工数を記録する運用を想定しています。既存項目とMCPで指定を省略した項目は従来どおり算入します。関連付けだけで自動的に工数を除外しないため、既存の課題は必要に応じて変更してください。過去の進捗履歴は通常の編集では再計算しません。

## 保管・復元

項目を選んで「編集 → 選択項目を保管」を開くと、無効になる依存関係と関連課題を確認できます。適用を明示して保管し、キャンセルでは保存しません。保管した項目は通常の一覧・カンバン・ガント・依存図・現在の工数集計から除きます。依存関係はデータとして保持し、保管項目につながる関係を日程計算・完了ゲート・依存図では無効にします。後続作業を阻止する関係も外れるため、保管前に影響を確認してください。

「絞り込み → 保管済みの項目を表示」で保管項目を確認し、「編集 → 保管した項目を復元」で選択して復元できます。同じID、全項目、依存関係を保持して戻します。関連課題からの参照も保持します。復元後は通常の絞り込みへ戻ります。

保管項目から参照される担当者・カテゴリ・確認者のマスタも削除できません。保管項目は20,000件の上限に含まれます。完全消去や保管世代の自動整理は未対応です。マスタの削除は保管ではなく削除です。形式5のDBは旧バージョンのアプリでは開けません。形式1・2・3・4は読み込め、最初の正常な書き込みと同時に形式5へ更新します。以前のアプリへ戻す必要がある場合は、更新前に終了済みDBのバックアップを残してください。

## MCPの分類・保管操作

`save_task` の追加項目は `priority`（low/normal/high/critical）、`severity`（unspecified/minor/major/critical）、`review`（not_required/pending/approved/changes_requested）、`reviewer`（担当者マスタID/null）、`review_note`、`include_in_effort`（既定true）、`related_tasks`（対応タスクID配列）、`archived`（既定false）です。既存項目は全項目置換なので、新項目も含め現在の値を取得してから変更してください。

`task_list` は `priority`、`severity`、`review`、`archived` でもAND検索できます。archived:false（既定）は通常項目のみ、trueは保管項目のみです。両方が必要なら `project_get` を使用します。

`removal_preview` に `project_id` と `task_id` を渡すと、版・対象項目・保持する依存関係・関連課題IDが返ります。読取専用でも使え、保存しません。確認後にプレビューのrevisionをexpected_revisionに指定して保管します。

```json
{"project_id":1,"expected_revision":42,"actor":"planner","change":{"operation":"remove_task","id":7}}
```

復元は `{"operation":"restore_task","id":7}` です。操作時点の版を必ず読み直します。影響確認はクライアントの手順であり、MCPがプレビュー呼出済みであることを強制する機構はありません。

復元できるのは新方式で保管した項目です。以前の版で完全削除した項目の自動復元は行いません。


## 階層・一覧のセル操作

タスク一覧の行を右クリックし「子タスクを追加」を選びます。子の行から同じ操作をすると孫タスクを作成できます。項目編集の「階層・節目」で親を変更できます。階層は件名の字下げで表示します。循環や存在しない親、課題を親とする指定は拒否します。親子の工数・進捗・日程はそれぞれ個別に管理し、自動合算・自動完了は行いません。

一覧は件名の左隣にカテゴリのパスを表示します。カテゴリのマスタ編集で親カテゴリを設定でき、最上位を含めて3階層まで作成できます。カテゴリ1・2・3の列でも各階層を確認できます。上位カテゴリの条件は配下も対象にします。

一覧のセルをクリックして選び、ドラッグまたはShift＋矢印で範囲を選択します。Ctrl+Cでタブ区切りの範囲をコピー、Ctrl+Vで既存の行へ貼り付けます。改行・タブ・引用符を含む値も引用付きTSVで扱います。F2・Enter・ダブルクリックでセルを編集し、Enterで保存、Escで取り消し、Tabで保存して次の列へ移ります。Shift+Enterはセル内の改行です。矢印・Tab・PageUp/PageDownで移動、Ctrl+Aで表示中の全範囲を選択できます。Deleteは選択セルを初期値へ戻します。必須の件名などが空になる操作は保存できません。

IDとカテゴリ1・2・3は読み取り専用です。担当者・カテゴリは名前、カテゴリのフルパス、またはマスタIDで編集できます。同じ名前が複数ある場合はIDかパスを使います。複数セルの貼り付けは1トランザクションで保存し、一部が不正なら全体を保存しません。完了・再開・レビューの条件は通常の編集と同じです。項目全体は右クリックの「項目を編集」で開きます。

行の移動は左端のID欄をつかんでドラッグし、青い挿入線の位置で離します。子孫をまとめて移動し、移動先の直前行と同じ親になります。末尾の空白へ移動すると最上位の末尾になります。子孫の中へ親を移動する操作は拒否します。絞り込み中も元のデータ全体の順序へ反映します。

## 列からの絞り込みと全文検索

タスク／課題一覧の列見出しを右クリックし、カテゴリ・担当者・状態などの値を選んで絞り込みます。空白の値も選べます。「値を入力して絞り込み」で任意の値を指定でき、「この列の絞り込みを解除」でその列だけ解除します。複数列の条件はANDで組み合わせます。絞り込み中の見出しには▼を付けます。候補は最大500値で、一覧外の値は入力欄から指定できます。

「検索 → タスクの全文検索」（Ctrl+F）は現在のプロジェクトのタスクと課題を横断し、件名・説明・確認メモ・担当者・確認者・カテゴリ・状態名・ID・日付を検索します。英字の大小を区別しない部分一致です。現在の列・状態などの条件も併用します。「すべて解除」で解除できます。ガントにも絞り込みを反映し、依存図・進捗チャートは案件全体を表示します。

## ガントとマイルストーン

ガントの日付見出しは上から年・月・日・曜日の4段です。休日を背景色で区別します。「ガント設定 → 表示起点・列幅・稲妻線」で起点の日付、項目／予定日程の列幅、1日の幅、稲妻線の表示と基準日を指定できます。項目／予定日程の列の右端をドラッグして幅を変更することもできます。設定は開いているウィンドウ内で保持します。

稲妻線は基準日と各項目の進捗位置を結んだ線です。未完了で開始済みの項目は予定期間上の進捗率の位置、未開始・完了・中止の項目は基準日につなぎます。開始日がない項目は基準日に接続します。実績日そのものの記録ではありません。

項目編集の「階層・節目」でマイルストーンを選び、日程の開始日または期限を指定します。同じ日付・期間0・工数0で保存し、ガントでは◆を表示します。依存関係にも指定できます。通常タスクの期間0は従来どおり1営業日として計算します。

## CSV出力

「ファイル → プロジェクトをCSV出力」で、検索語・カテゴリ・担当者・状態・種類を指定します。現在の列などの絞り込みも適用します。「出力列1～5」の各列を「出力する／出力しない」で選択します。ID・親ID・カテゴリ階層・説明・確認メモ・日程・マイルストーンなどを選べます。

CSVはUTF-8 BOM付き、CRLF区切りで、改行・カンマ・引用符を含む値は引用します。出力順は一覧と同じ階層・兄弟順です。CSVは選択した項目の受け渡し用で、DB全体や監査のバックアップではありません。DB全体の移送にはSQLiteへの書き出しを使います。

## Jira用CSV

「ファイル → Jira用CSVを出力」でJira Cloudの会社管理プロジェクト用CSVを保存します。検索語と現在の絞り込みを適用し、親が欠けないよう祖先も含めます。3階層はEpic／Task／Sub-task、2階層はTask／Sub-task、最上位の課題はBugです。タイプ名と追加列を選択できます。深すぎる階層や改行付き・255文字を超える件名は出力できません。

Jiraの管理者向け外部システムCSV取り込み（既存の画面）で、Summary・Issue Type・Issue ID・Parentを対応付けます。期限の日付形式はyyyy-MM-ddです。状態・優先度は取り込み先の値へ対応付けます。担当者は初期設定では出力せず、出力時は名前をJiraのアカウントとして解決できる値へCSV上で変更してください。繰り返し取り込むと重複登録になります。詳しくは配布物のdocs/user/jira-csv.mdを参照してください。

## PostgreSQL・移行の操作

`.env.example` を `.env` へコピーしてパスワードを設定し、`docker compose up -d --wait postgres` で起動します。接続先は127.0.0.1:15432、DBとユーザーはyyprojectです。`python tools/with_postgres.py yyprojectw.exe --postgres` でGUI、`python tools/with_postgres.py yyproject.exe --mcp-postgres` でMCPを起動できます。直接起動時は接続文字列をYYPROJECT_DATABASE_URLに設定します。

`yyproject --migrate-to-postgres SOURCE_SQLITE` は空のPostgreSQL領域へ全案件・履歴・監査を移します。`yyproject --export-sqlite NEW_SQLITE` は新しいSQLiteファイルへ書き出します。いずれもYYPROJECT_DATABASE_URLを使用し、Compose補助スクリプトからも実行できます。GUIのファイルメニューにも接続・移行・書き出しがあります。既存データへ上書きや統合をしません。詳しくは配布物のdocs/user/postgresql.mdを参照してください。

MCPのsave_taskにはparent（親タスクID）とmilestone、save_masterにはparent（親カテゴリID）を指定できます。save_tasksは既存タスク最大2000件の一括保存、move_taskはidをbefore（直前に挿入するタスクID、nullで最上位末尾）へ子孫ごと移動します。task_listのcolumnsは列キーと表示値の完全一致によるAND条件です。categoryは下位カテゴリも含めます。DB形式5へ更新したファイルは旧アプリでは開けません。

## 一覧の列幅・行高と複数行の属性変更

タスク／課題一覧とマスタ一覧は、列見出しの境界を左右にドラッグして列幅を変更できます。各データ行の下端を上下にドラッグすると、その行の高さを変更できます。ガントは「項目／予定日程」の右端で名前列の幅、同じ列の各行の下端で行高を変更します。日付見出しの下2段の列境界では1日分の幅も変更できます。境界上ではカーソルが変わります。Esc・右クリック・キャプチャ喪失で変更前の寸法へ戻し、マウスを離すと確定します。寸法はウィンドウ内で保持し、DBの版や監査を更新しません。

タスク／課題一覧でShift＋クリックやセル範囲選択により複数行を選択します。Ctrl＋クリックで離れた行を追加・解除できます。対象行を右クリックして「選択行の属性を一括変更」、または編集メニューの同名項目を選びます。担当者・カテゴリ・状態・優先度・開始日・期限・完了日・進捗を指定できます。各属性は「変更しない」「指定値に変更」「空／初期値にする」から選びます。絞り込みで見えない項目や選択していない子孫は変更しません。

完了日は予定の期限とは別の実績日（completed_on）です。空白も可能で、入力によって状態や進捗を自動変更しません。通常の項目フォームと一覧セルでも編集でき、CSV・MCP・SQLite／PostgreSQL移送にも含まれます。状態を完了にする場合の先行項目やレビューの条件は従来どおりです。一括変更は全対象を検証して1回の版更新・監査・トランザクションで保存し、条件違反や他接続との版競合があれば全体を保存しません。

## マスタ一覧の直接編集

マスタタブの中で「カテゴリ」「担当者」「休日」を切り替え、選択した種類だけを表示します。カテゴリはID・名前・親カテゴリID、担当者はID・名前、休日はID・名前・休日の日付を表示します。他の種類の項目や不要な列は表示せず、種類そのものはセルから変更しません。F2／Enter／ダブルクリックで直接編集し、Enterで保存、Escで取り消し、Tabで隣へ移ります。Ctrl+C／Ctrl+Vの矩形コピー・貼り付けは表示中の種類だけを対象にします。IDは読み取り専用です。カテゴリの循環・4階層目など不正な値は保存できません。新規追加とマスタ自体の削除は編集メニューを使います。Deleteキーはセル値を空にする操作で、行は削除しません。

## 日次チャートと依存ネットワークの選択

バーンダウン／バーンアップは日単位の縦格子、「曜日・日・月・年」の4段の日付軸（日の数字は起点から7日ごと）、ガントと同じ休日判定・背景色を使います。期間が長い場合は横スクロールして確認します。実績の線とガントの稲妻線はDPIに応じた太さで表示します。実績のない日の値を生成することはせず、記録された日付の点を結びます。

依存ネットワークで項目をクリックすると、その項目と、依存関係を遡る先行項目・辿る後続項目を強調します。他の項目・矢印は薄く表示します。同じ先行項目から分岐しただけの別系統は強調対象に含めません。余白をクリックすると全体表示へ戻ります。

## Streamable HTTPサーバー・PAT認証

`yyproject --generate-pat USER --auth-config yyproject-server.toml [--read-only]` でユーザーのPATを生成します。表示されたPATを保存し、クライアントのHTTPヘッダーへ `Authorization: Bearer <PAT>` として設定します。設定ファイルにはユーザー名・SHA-256ハッシュ・読み取り専用設定を保存します。同じユーザー名で再生成すると更新でき、ユーザー削除とPAT更新は次のHTTP要求から有効です。

SQLiteは `yyproject --mcp-http DATABASE --auth-config yyproject-server.toml`、PostgreSQLは `yyproject --mcp-http-postgres --auth-config yyproject-server.toml` で起動します。PostgreSQLにはYYPROJECT_DATABASE_URLを設定するかCompose補助スクリプトを使います。エンドポイントはhttp://127.0.0.1:8740/mcpです。`--listen IP:PORT`で変更、`--read-only`で全ユーザーを読み取り専用にできます。GUIとは別の常駐プロセスです。

Streamable HTTPのJSON応答を使い、SSE配信は行いません。監査のactorは認証したユーザー名になります。PATごとにセッションを分離し、Host・Originを検証します。外部接続時は設定のserver.allowed_hostsを明示し、HTTPSリバースプロキシを使ってください。詳しい設定例はdocs/user/mcp-http.mdにあります。

## 同じ列の値を下方向へコピー

コピー元を先頭行に含めて同じ列の複数セルを選び、Ctrl+D、または編集メニューの「選択範囲を下方向にコピー」を実行します。各列の先頭セルを同じ列の下の選択セルへコピーします。1セルだけコピーしたテキストを、同じ列の複数セルへCtrl+Vで貼り付けても、選択範囲へ同じ値を入れられます。Ctrl選択した離れたタスク行も対象にできます。表示外・未選択の行は変更せず、不正な値や完了条件に違反する場合は全体を保存しません。

タスクの一括変更・下方向コピー・複数行貼り付けで変更できる属性は、担当者・カテゴリ・状態・優先度・開始日・期限・完了日・進捗です。件名は「個別」、それ以外の個別編集専用列は※を見出しに付けます。複数行の選択時は該当セルを灰色で表示し、一括での上書き・消去を拒否します。件名・説明・親タスクなどは1セルを選択して編集してください。複数行から項目編集を開いた場合も、個別フォームではなく属性の一括変更画面を表示します。


## バグ管理・課題管理

「編集 → バグを追加／課題を追加」で登録し、専用一覧で管理します。工程・原因・暫定／恒久対策案・3種類の難易度・10種類の日時・対応タスクを記録できます。詳細フォームのタブを切り替えて入力し、日時は2026-10-27T09:00:00+09:00の形式で指定します。

両一覧はタスク一覧と同じセル編集、範囲コピー、Ctrl+D、同列への1セル貼り付け、Shift/Ctrlの行選択、属性一括編集、列の値による右クリックフィルタ、列幅・行高の境界ドラッグ、ID列からの行移動に対応します。原因・工程・難易度・対策予定日時・完了／中止日時も一括編集できます。件名・対策案・発生／検出など個別日時は個別編集専用です。

「ファイル → バグ一覧をCSV出力／課題一覧をCSV出力」で、出力列と絞り込みを選べます。現在の一覧・統計で「プロジェクトをCSV出力」を使っても専用列を選択できます。

「バグ統計」「課題統計」はタスクのバーンダウンと同じ日次格子・休日色・曜日／日／月／年・太い線を使い、縦軸は未完了件数です。完了・中止・再オープンを履歴から集計します。原因・発生工程・検出工程・3種類の難易度は件数と割合の棒グラフにします。集計期間は「統計設定」で指定し、現在の絞り込みと現在の分類を使用します。検出日時がない旧課題は別枠の未記録件数とし、日付を推測しません。日時はUTCへ統一して集計します。

MCPのcase_statisticsは読み取り専用で、kind（bug／issue）、from、to、任意のfilterを指定できます。project_changeのsave_taskはcase内の調査属性を保存し、状態履歴はサーバーが保持します。保存形式は5です。
